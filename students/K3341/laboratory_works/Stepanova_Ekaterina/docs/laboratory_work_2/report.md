### Задание 5

URL-маршрутизация в Django работает через файл urls.py. Каждый URL-паттерн связывает адрес с конкретным представлением.

Структура: в проекте есть главный urls.py (рядом с settings.py), который включает urls.py приложений:

```# urls.py проекта (blogfspo/urls.py)
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('project_first_app.urls')),  
]

```

include() подключает список маршрутов приложения по префиксу '' (то есть без изменений). Если бы вместо '' был указан '
app/', все адреса приложения оказались бы вложены под /app/... — сам urls.py приложения при этом менять не пришлось бы.

Создали в приложении свой urls.py

```
# urls.py приложения
from django.urls import path
from . import views

urlpatterns = [
    path('owner/<int:owner_id>/', views.owner_detail),  
]
```

<int:owner_id> — конвертер типов. Django извлечёт из этой части URL целое число, отклонив запрос (вернёт 404) для
нечислового значения, и передаст его функции owner_detail как именованный аргумент owner_id.

### Задание 3

Форма — интерфейс для создания и редактирования данных. Django предоставляет класс ModelForm, который автоматически
генерирует форму на основе модели: поля формы создаются из полей модели, валидация тоже берётся из модели.

Метод is_valid() делает три вещи: проверяет заполненность обязательных полей, запускает валидаторы и сохраняет очищенные
данные в form.cleaned_data. Если валидация провалилась — форма с ошибками рендерится заново, Django сам подставляет
сообщения об ошибках рядом с полями.

Я создаю файл forms.pyб нужен для того, чтобы управлять вводом данных от пользователя на сайт.

Внутри самого класса формы CarOwnerForm вы описываете поведение формы, а внутри class Meta вы даёте Django инструкцию,
из чего и как эту форму вообще собрать.

ModelForm строит поля формы и правила валидации из полей указанной модели — отдельно описывать title =
forms.CharField(...) не нужно.

fields - Явный список полей обязателен: без него ModelForm выбросит исключение при определении класса. Перечислять все
поля модели не обязательно — форма будет работать только с указанными.

В рамках выполнения Практического задания 3 (в конце Практики 2.2) данный механизм `ModelForm` был применен для создания
формы `CarOwnerForm`. В файле `views.py` была написана функция-представление `create_owner`, реализующая классический
паттерн обработки веб-форм:

1. **GET-запрос:** если пользователь просто открывает страницу, создается пустой экземпляр формы `form = CarOwnerForm()`
   и рендерится HTML-шаблон.
2. **POST-запрос:** при отправке данных из веб-интерфейса, форма инициализируется переданными данными
   `CarOwnerForm(request.POST)`. Далее вызывается метод `form.is_valid()`. Если валидация пройдена, метод `form.save()`
   автоматически генерирует SQL-запрос `INSERT` и создает новую запись автовладельца в СУБД SQLite, после чего
   срабатывает перенаправление (`redirect`) на список.

Код реализации во `views.py` (до глобального рефакторинга на AbstractUser):

```
def create_owner(request):

        form = CarOwnerForm(request.POST)

            form.save()  # Автоматически создает объект в базе данных
            return redirect('owners_list')
    else:
        form = CarOwnerForm()
    return render(request, 'owners/create_owner.html', {'form': form})
```

### Редактирование и удаление владельца

Помимо добавления нового владельца, в приложении реализованы функции редактирования и удаления существующих владельцев.

Для редактирования используется функциональное представление `owner_update`. Сначала с помощью функции
`get_object_or_404` из базы данных получается объект `CarOwner` по переданному идентификатору:

```python
def owner_update(request, pk):
    owner = get_object_or_404(CarOwner, pk=pk)

    if request.method == 'POST':
        form = CarOwnerForm(request.POST, instance=owner)
        if form.is_valid():
            form.save()
            return redirect('owners_list')
    else:
        form = CarOwnerForm(instance=owner)

    return render(
        request,
        'owners/create_owner.html',
        {'form': form, 'title': 'Редактировать владельца'}
    )
```

При GET-запросе форма заполняется текущими данными выбранного владельца. При POST-запросе данные из формы передаются в
`CarOwnerForm` вместе с параметром `instance=owner`. Это позволяет изменить уже существующий объект, а не создать новый.

После успешной проверки данных вызывается `form.save()`, после чего выполняется перенаправление на страницу со списком
владельцев.

Для удаления владельца реализовано отдельное функциональное представление:

```python
def owner_delete(request, pk):
    owner = get_object_or_404(CarOwner, pk=pk)

    if request.method == 'POST':
        owner.delete()
        return redirect('owners_list')

    return render(
        request,
        'owners/owner_confirm_delete.html',
        {'owner': owner}
    )
```

При открытии страницы удаления отображается шаблон `owner_confirm_delete.html`, в котором пользователь может подтвердить
удаление. При отправке POST-запроса объект владельца удаляется из базы данных.

Таким образом, для владельцев в приложении реализованы операции просмотра списка и отдельного владельца, создания,
редактирования и удаления.

### Реализация представлений для автомобилей

Для работы с автомобилями в приложении используются классы Django CBV (Class-Based Views).

Получение списка автомобилей реализовано с помощью `ListView`:

```python
class CarListView(ListView):
    model = Car
    template_name = 'cars/cars_list.html'
```

В качестве модели указывается `Car`, а результат работы представления отображается в шаблоне `cars/cars_list.html`.

Для просмотра информации об отдельном автомобиле используется `DetailView`:

```python
class CarDetailView(DetailView):
    model = Car
    template_name = 'cars/car_detail.html'
```

Представление получает объект `Car` по идентификатору и передаёт его в шаблон `cars/car_detail.html`.

### Создание автомобиля

Создание автомобиля реализовано с помощью `CreateView`:

```python
class CarCreate(CreateView):

    template_name = 'cars/create_car.html'
```

В представлении указывается модель `Car`, а также поля, которые должны быть доступны для заполнения:

страницу списка автомобилей.

### Обновление автомобиля

Изменение данных автомобиля реализовано с помощью `UpdateView`:

```python
class CarUpdateView(UpdateView):

```

`UpdateView` автоматически получает существующий объект `Car`, отображает его данные в форме и после отправки формы
сохраняет изменения.

Для редактирования используется шаблон `cars/update_car.html`. После успешного изменения пользователь возвращается к
списку автомобилей.

### Удаление автомобиля

Для удаления автомобиля используется `DeleteView`:

```python
class CarDelete(DeleteView):
    model = Car
    template_name = 'cars/car_confirm_delete.html'
    success_url = reverse_lazy('cars_list')
```

Перед удалением отображается страница подтверждения с использованием шаблона `cars/car_confirm_delete.html`. После
подтверждения объект удаляется, а пользователь перенаправляется на список автомобилей.

В данном случае для `success_url` используется `reverse_lazy('cars_list')`, то есть адрес страницы определяется по имени
маршрута.

### Модель Flight

Эта модель отвечат за авиарейсы.

```
class Flight(models.Model):
    FLIGHT_TYPE_CHOICES = [('departure', 'Отлёт'),('arrival', 'Прилёт'),]
    flight_number = models.CharField(max_length=20,verbose_name='Номер рейса')
    airline = models.CharField(max_length=100, verbose_name='Авиакомпания')
    departure = models.CharField( max_length=100, verbose_name='Отлёт')
    arrival = models.CharField(max_length=100, verbose_name='Прилёт')
    flight_type = models.CharField(max_length=20, choices=FLIGHT_TYPE_CHOICES, verbose_name='Тип')
    gate = models.CharField(max_length=20, verbose_name='Гейт')
    departure_time = models.DateTimeField(verbose_name='Время вылета')
    arrival_time = models.DateTimeField(verbose_name='Время прилёта')
    class Meta:
        ordering = ['departure_time']
        verbose_name = 'Рейс'
        verbose_name_plural = 'Рейсы'

    def __str__(self):
        return f'{self.flight_number} — {self.airline}'
```

`FLIGHT_TYPE_CHOICES` - список кортежей для создания выпадающего списка. Первый элемент ('departure') сохраняется в базу данных, а второй ('Отлёт') - это понятный человеку текст, который отобразится в админ-панели Django или на формах.

`verbose_name='Авиакомпания'` - аргумент, который используется в веб-фреймворке для создания понятного человеку названия поля или модели.

`flight_type (CharField)` — тип рейса. Благодаря параметру choices=FLIGHT_TYPE_CHOICES Django будет строго контролировать, чтобы в это поле нельзя было записать ничего, кроме 'departure' или 'arrival'

#### Класс Meta

Вложенный класс Meta используется для изменения поведения модели внутри Django:

`ordering = ['departure_time']` - обычная сортировка. Когда мы будем запрашивать рейсы из базы данных (например, Flight.objects.all()), Django автоматически отсортирует их по времени вылета от самых ранних к самым поздним.

`verbose_name и verbose_name_plural` - понятное имя модели в единственном и множественном числе для панели администратора (Рейс / Рейсы). Без этого Django просто отобразил бы имя класса во множественном числе как Flights.

### Модель Reservation

Отвечает за бронирование мест пользователем.

```
class Reservation(models.Model):
    user = models.ForeignKey(User, on_delete=models.CASCADE,related_name='reservations', verbose_name='Пользователь')
    flight = models.ForeignKey(Flight, on_delete=models.CASCADE, related_name='reservations', verbose_name='Рейс')
    seat_number = models.CharField( max_length=10, verbose_name='Номер места')
    ticket_number = models.CharField(max_length=30, blank=True, verbose_name='Номер билета')
    created_at = models.DateTimeField( auto_now_add=True, verbose_name='Дата резервирования')
    class Meta:
        ordering = ['-created_at']
        verbose_name = 'Резервирование'
        verbose_name_plural = 'Резервирования'

        constraints = [
            models.UniqueConstraint(
                fields=['flight', 'seat_number'],
                name='unique_flight_seat'
            )
        ]

    def __str__(self):
        return f'{self.user.username} — {self.flight.flight_number} — место {self.seat_number}'
```

Здесь у нас присутствуют связи между таблицами (один ко многим), это в полях user и flight, один пользователь может сделать много бронирование и один рейс может иметь много бронирований.

Важно обратить внимание на:

`on_delete=models.CASCADE` - если аккаунт пользователя будет удален, все его бронирования автоматически удалятся из базы.

`related_name='reservations'` - позволяет легко получить все бронирования пользователя прямо через его объект related_name='reservations'

Аналогичные рассуждения и для flight.

`blank=True` в ticket_number означает, что поле не обязательно для заполнения при создании записи.

`auto_now_add=True` - Django автоматически подставит текущую дату и время в момент создания записи. Вручную это поле заполнять или редактировать нельзя.

#### Класс Meta

`ordering = ['-created_at'] — знак минуса - означает сортировку по убыванию. Новые бронирования всегда будут отображаться вверху списка (первыми)`

`
constraints = [
            models.UniqueConstraint(
                fields=['flight', 'seat_number'],
                name='unique_flight_seat'
            )
        ]
`
UniqueConstraint (Уникальное ограничение): Это правило на уровне самой базы данных, которое гарантирует, что на один и тот же рейс нельзя забронировать одно и то же место дважды.

Если система попытается создать запись на рейс SU-2130 с местом 12A, когда такое место уже занято, база данных заблокирует этот запрос и выбросит ошибку.

```
def home(request):
    flights = Flight.objects.all()
    query = request.GET.get('q', '').strip()
    if query:
        flights = flights.filter(
            Q(flight_number__icontains=query)
            | Q(airline__icontains=query)
            | Q(departure__icontains=query)
            | Q(arrival__icontains=query)
        )
    flight_type = request.GET.get('type', '')
    if flight_type in ['departure', 'arrival']:
        flights = flights.filter(flight_type=flight_type)
    date = request.GET.get('date', '').strip()
    if date:
        flights = flights.filter(departure_time__date=date)
    sort = request.GET.get('sort', 'departure_time')
    allowed_sort = ['departure_time', '-departure_time', 'flight_number', '-flight_number', 'airline', '-airline',]
    if sort not in allowed_sort:
        sort = 'departure_time'
    flights = flights.order_by(sort)
    paginator = Paginator(flights,4)
    page_number = request.GET.get('page')
    page_obj = paginator.get_page(page_number)
    query_params = request.GET.copy()
    if 'page' in query_params:
        query_params.pop('page')

    return render(
        request,
        'flights/home.html',
        {
            'page_obj': page_obj,
            'query': query,
            'flight_type': flight_type,
            'date': date,
            'sort': sort,
            'query_params': query_params.urlencode(),
        }
    )
```

Что мы тут делаем:

`flights = Flight.objects.all()` - вытаскиваем все рейсы из баз данных

```
@login_required
def create_reservation(request, flight_id):
    flight = get_object_or_404(Flight, id=flight_id)

    if request.method != 'POST':
        return render(request, 'flights/reservation_form.html', {'flight': flight})

    seat_number = request.POST.get('seat_number', '').strip()

    if not seat_number:
        messages.error(request, 'Укажите номер места.')
        return render(request, 'flights/reservation_form.html', {'flight': flight})

    if Reservation.objects.filter(flight=flight, seat_number=seat_number).exists():
        messages.error(request, 'Это место уже забронировано.')
        return render(request, 'flights/reservation_form.html', {
            'flight': flight,
            'seat_number': seat_number,
        })

    Reservation.objects.create(
        user=request.user,
        flight=flight,
        seat_number=seat_number,
        ticket_number=''
    )

    messages.success(request, 'Место успешно забронировано.')
    return redirect('my_reservations')
```

@login_required - Гарантирует, что забронировать место может только авторизованный пользователь. Гостя сайта Django автоматически перенаправит на страницу логина.

```def register(request):
    if request.method != 'POST':
        return render(request, 'flights/register.html')

    username = request.POST.get('username', '').strip()
    password = request.POST.get('password', '')
    password2 = request.POST.get('password2', '')

    if not username or not password:
        messages.error(request, 'Заполните все поля.')
        return render(request, 'flights/register.html')

    if password != password2:
        messages.error(request, 'Пароли не совпадают.')
        return render(request, 'flights/register.html')

    if User.objects.filter(username=username).exists():
        messages.error(request, 'Пользователь с таким логином уже существует.')
        return render(request, 'flights/register.html')

    user = User.objects.create_user(username=username, password=password)
    login(request, user)
    
    return redirect('home')
```

```
def login_view(request):
    if request.method != 'POST':
        return render(request, 'flights/login.html')

    username = request.POST.get('username', '').strip()
    password = request.POST.get('password', '')
```
